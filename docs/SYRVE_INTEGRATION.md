# Підключення Syrve Cloud API

Пульт Директора підтримує перевірку API-доступу, вибір організації, безпечне збереження, повторну перевірку та відключення Syrve.

## Обов’язкове налаштування сервера

У production потрібно встановити окремий довгий випадковий секрет:

```env
SYRVE_CREDENTIALS_SECRET=replace-with-a-long-random-secret
```

Дані API-логіна шифруються на backend через AES-256-GCM. Повний логін після збереження не повертається у frontend.

## Обмеження першого етапу

Підключення підтверджує доступ до Cloud API та організації. Синхронізація столів, замовлень і статусів у цьому етапі не ввімкнена.

Дозволені лише HTTPS-адреси офіційних доменів `*.syrve.live` та `*.iiko.cloud`.

## Перевірка конкретного рахунку

У збереженому підключенні Директор може вручну ввести UUID рахунку та натиснути «Перевірити рахунок». Перевірка доступна і під час автоматичної синхронізації. Вона не змінює статуси, зв’язки столів або бронювання.

`POST /syrve-integration/bill-diagnostics` приймає лише `configurationRevision` та `orderId` (UUID). Операція використовує збережені зашифровані дані доступу, перевірку ролі Директора, спільний ліміт запитів Syrve та наявний механізм асинхронних операцій. Frontend опитує лише MOLO з чинним інтервалом 15 секунд; повторний POST автоматично не надсилається.

Backend спочатку читає `/api/1/order/by_id` із `posOrderIds`, а лише після коректної порожньої відповіді — із `orderIds`. Селектори взаємно виключні: невикористане поле має значення `null`. POS UUID та Cloud UUID можуть відрізнятися. Знайдений рахунок перевіряється за організацією та відповідним ідентифікатором; помилка, неповна відповідь або зміна налаштувань зупиняють перевірку.

Результат містить номер, стан, UUID рахунку у Cloud/POS, версію, UUID касової групи та столів із точними наявними зв’язками MOLO. Дані гостей, позиції, платежі, ключі доступу та необроблені відповіді не повертаються. Відсутність рахунку не доводить його закриття. UUID з іншої системи, зокрема Expirenza, потребує перевірки і не вважається UUID Syrve автоматично. Діагностика не створює рахунків і не виконує команд у POS.
